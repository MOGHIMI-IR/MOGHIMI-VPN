## ✨ امکانات اصلی

- اتصال VPN واقعی از طریق Android VpnService و هسته Xray.
- همگام‌سازی کانفیگ‌های فعال سایت مقیمی از Supabase؛ کانفیگ‌های ابری در گروه جداگانه نگهداری می‌شوند.
- افزودن و مدیریت کانفیگ‌های شخصی از طریق لینک، متن، Clipboard، فایل و QR.
- جلوگیری از کپی و اشتراک‌گذاری کانفیگ‌های گروه ابری مقیمی؛ کانفیگ‌های شخصی کاربر مستقل باقی می‌مانند.
- اتصال هوشمند: آزمایش تأخیر واقعی کانفیگ‌های گروه مقیمی و انتخاب کانفیگ دارای کمترین تأخیر معتبر.
- نمایش وضعیت اشتراک و سهمیه، ثبت پروفایل دستگاه و فعال‌سازی کد اشتراک.
- مدیریت قطع و وصل شبکه و تلاش مجدد برای بازیابی هسته VPN.
- رابط کاربری اختصاصی با انیمیشن‌های بومی Compose.

## ☁️ همگام‌سازی کانفیگ‌ها

کانفیگ‌های فعال سایت مقیمی در گروه ابری برنامه دریافت می‌شوند. همگام‌سازی هنگام اجرای برنامه، از طریق دکمه ابر و به‌صورت دوره‌ای انجام می‌شود. اجرای پس‌زمینه به WorkManager و محدودیت‌های باتری و زمان‌بندی Android وابسته است.

کانفیگ‌هایی که در پنل سایت غیرفعال یا حذف شوند، پس از همگام‌سازی بعدی از گروه ابری برنامه کنار می‌روند. کانفیگ‌های شخصی کاربر در گروه خودشان باقی می‌مانند.

## 🛠️ تغییر مهم نسخهٔ ۲.۰.۱۰

در این نسخه، شناسهٔ User-Agent همگام‌سازی ابری و مدیریت مجوز از شمارهٔ نسخهٔ واقعی برنامه خوانده می‌شود؛ پاسخ مشخصِ نیاز به به‌روزرسانی نیز دیگر به خطای عمومی «سرور پاسخ نمی‌دهد» تبدیل نمی‌شود.

## 🔄 سامانه به‌روزرسانی

برنامه در شروع اجرا و پیش از برقراری اتصال، نسخه فعال ثبت‌شده در Supabase را بررسی می‌کند. پس از انتشار نسخه جدید، API آخرین نسخه فعال را به کلاینت‌ها اعلام می‌کند. نسخه‌های قدیمی‌تر پیام و پنجره به‌روزرسانی اجباری دریافت می‌کنند و امکان شروع یا ادامه اتصال با نسخه منسوخ‌شده محدود می‌شود.

فایل APK در Storage قرار می‌گیرد و وب‌هوک ثبت انتشار، شماره نسخه و SHA-256 آن را در جدول `app_releases` ثبت می‌کند. GitHub Actions نیز تطبیق فایل آپلودشده با فایل ساخته‌شده را بررسی می‌کند.

اعلان برنامه از طریق قابلیت اعلان محلی Android انجام می‌شود؛ پوش نوتیفیکیشن از راه دور برای زمانی که برنامه کاملاً بسته است در این پروژه فعال نشده است. نصب نهایی APK از مسیر استاندارد Android و با تأیید کاربر انجام می‌شود.

## 🔧 ساخت و انتشار APK

گردش‌کار GitHub Actions در `.github/workflows/android-apk.yml` سورس و submodule پین‌شده v2rayNG، ابزار TUN و کتابخانه Xray را آماده می‌کند؛ تست‌های واحد را اجرا می‌کند و خروجی **ARM64** را در GitHub Releases منتشر می‌کند.

برای اجرای دستی: GitHub → Actions → Build Moghimi V2Ray APK → Run workflow.

انتشار فعلی با keystore ثابت مقیمی امضا شده است تا امکان به‌روزرسانی روی نصب قبلیِ دارای همان گواهی حفظ شود. فایل keystore و رمزهای آن در مخزن عمومی قرار نمی‌گیرند و فقط از GitHub Actions Secrets خوانده می‌شوند.

## 🔐 امنیت، Supabase و حریم خصوصی

- برنامه از publishable key عمومی استفاده می‌کند؛ کلید service-role یا رمز مدیریتی داخل APK قرار نگرفته است.
- کلید مدیریتی Storage فقط در GitHub Actions Secret نگهداری می‌شود تا CI بتواند APK را به Storage آپلود کند.
- اطلاعات سفارش‌ها و اطلاعات خصوصی مدیریت از کلاینت عمومی برنامه خوانده نمی‌شوند.
- ترافیک VPN از Android VpnService به سرور انتخاب‌شده در کانفیگ می‌رود و از Supabase عبور نمی‌کند.
- کانفیگ‌های گروه ابری مقیمی از قابلیت کپی و اشتراک‌گذاری داخل برنامه محافظت می‌شوند؛ این محدودیت برای کانفیگ‌های شخصی کاربر اعمال نمی‌شود.

## 🧪 وضعیت انتشار و آزمایش

نسخه **۲.۰.۱۰ (Build 103 / Beta 103)** در GitHub Actions ساخته و منتشر شده است. تست‌های واحد، ساخت APK، بررسی امضای پایدار، آپلود فایل در Supabase، تطبیق SHA-256 و ثبت خودکار نسخه در `app_releases` موفق بوده‌اند.

در این انتشار، بررسی‌های CI شامل تست‌های واحد، ساخت APK، بررسی امضای پایدار، وجود فایل native مربوط به TUN در APK، آپلود و تطبیق SHA-256 در Supabase و ثبت نسخهٔ فعال با موفقیت انجام شده‌اند. آزمایش نهایی اتصال و بازیابی شبکه روی مدل‌های مختلف گوشی همچنان باید روی دستگاه واقعی انجام شود. این نسخه با برچسب **Beta** منتشر شده و نباید به‌عنوان نسخه‌ای که روی تمام دستگاه‌ها آزمایش شده معرفی شود.
